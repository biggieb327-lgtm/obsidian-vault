## Infrastructure Finding — Hindsight LLM path BROKEN (auth.lock)

- `/health` returns `{"status":"healthy","database":"connected",...}` — DB and
  embeddings are up.
- But `POST /v1/default/banks/hermes-agent/reflect` fails:
  `Permission denied: '/home/hindsight/.hermes/auth.lock'`.
- **Root cause (diagnosed, read-only):** the container's `/home/hindsight/.hermes/`
  directory is `root:root`, mode `0755` (`drwxr-xr-x`). The Nous auth manager
  writes `auth.lock` there during token refresh; uid 1000 (`hindsight`) cannot
  write to a root-owned 0755 dir. The `auth.json:ro` single-file bind mount is
  fine — the *directory* around it is the problem.
- This is the skill-documented failure class: "`/health` green does not mean the
  LLM path works." `/health` only proves DB + embeddings.
- **Why now:** auth.lock is written on token refresh; a refresh was evidently
  triggered today, exposing a permission state that was latent since the
  single-auth container was recreated 09-14.
- **Proposed fix (privileged, Sovereign-approval):** make the container's
  `.hermes` dir writable by the hindsight user, e.g.
  `sg docker -c "docker exec hindsight chown hindsight:hindsight /home/hindsight/.hermes"`.
  This keeps `auth.json` as a `:ro` bind (single source of truth) while allowing
  `auth.lock` writes. Recreated containers revert this (dir is in the writable
  layer), so it should be baked into the recreate step (`hindsight_single_auth.sh`).
