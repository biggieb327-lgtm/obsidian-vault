## Finding 1 — the dreaming job only ever sees ~3 hours of each day (script defect)

`dreaming_job.py:26` keys the window on the **current UTC date**:

```python
TODAY = datetime.now(timezone.utc).strftime("%Y-%m-%d")   # line 26
if stripped.startswith(TODAY):                            # line 72
```

Log lines carry **local** timestamps, and the job fires at 03:00 local
(01:00 UTC), so "today" resolves to at most 00:00–03:00 local. Measured today:
`2026-09-15` = 11,108 log entries, of which **0** were ever considered;
`2026-09-16` = 4,050 entries, all of which were. The note that says "2026-09-15"
was in fact only ever about 00:00–03:00 on the 15th.

Consequence: the nightly note systematically misses the entire working day —
including every user conversation — while announcing a full-day scan.

**Proposed fix (4 lines, awaiting approval — changes what the note contains):**
name the note by the local run date, but filter on the local-date set
`{yesterday, today}`, so the 03:00 run covers the day that just ended.

## Finding 2 — the extractor's "action items" are noise (quality defect)

6 items, 0 with an owner, a deadline, or a next step; 0 decisions and 0 project
